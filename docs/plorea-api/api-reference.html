Reference

API reference

Every endpoint of the Plorea Payments API, with its parameters, a request in three languages, the real response shape, the errors it returns and whether you can retry it safely. The guides explain the workflows. This page is the contract.

Where the shapes come from

Every response example is a real capture from the Plorea test environment, anonymised. Identifiers such as sub_test_golden and TESTPSPREF000001 replace the real values. Field names, nesting, key order and null values are as Plorea returned them. Badges mark where behaviour was verified, stated by Plorea or is still open. See How to read the badges.

Basics

Base URL

https://payments.plorea.no

Test and live share the host. The X-Environment header selects the Adyen account.

Request headers

HeaderValueDescription
AuthorizationrequiredBearer plr_test_FAKE…Your API key. Plorea issues it. Test keys start with plr_test_.
X-Environmentsend alwaystest | liveSelects the Adyen credentials. A refund without this header goes to live credentials and fails with 401 "errorType": "security". Verified
Content-Typeapplication/jsonOn POST and PATCH.
Acceptapplication/jsonRecommended on every request.

The platform field

Send platform on every request: in the JSON body on POST and PATCH, in the query string on GET. The value names your integration, for example acme. Plorea uses it for logging and reporting. It has no functional effect. Stated by Plorea The parameter tables below do not repeat it.

Amounts

All amounts are integers in minor units (øre). 10000 is 100,00 kr. Payment links and refunds take a flat integer amount plus a currency string. Subscriptions and charges take an Amount object:

{ "value": 29900, "currency": "NOK" }

Errors

A failed request returns a JSON body with an error string. Some errors add context keys, for example status or paymentMethodId. Branch on the HTTP status. The messages are fixed templates: a request that misses two required fields lists all of them. Never parse a message. Verified

StatusMeaningPHP SDK exception
400Validation failed, or the object is in the wrong state (not chargeable, card not active, not canceled, a status change that is not allowed).ValidationException. A card still in use on delete: PaymentMethodInUseException, a subclass.
401Bad API key, or wrong environment credentials.AuthenticationException
402The card was declined on a subscription charge. Nothing else returns 402.ChargeFailedException
403Tenant mismatch: the object belongs to another tenant.AuthenticationException
404Unknown reference or ID.NotFoundException
5xxPlorea or Adyen failed.ServerException

See Errors and retries for handling patterns.

Not safe to retry

A timeout does not tell you if the link exists. A blind retry can give the customer two payable links. Before you retry, call GET /payments/status/{reference}. A 404 means you can create. A paid status means stop. The PHP SDK does this walk in firstOrCreate().

Refund a payment

POST/payments/refund

Returns money for a payment that has settled. For a payment that has not settled yet, cancel it. Guide: Refunds and cancellations.

Send X-Environment: test

Without the header, this endpoint uses the live Adyen credentials. A test key then fails with 401 and "errorType": "security". The error looks like a bad key. Verified

Body parameters

FieldTypeDescription
referencerequiredstringThe payment reference.
modificationReferencerequiredstringYour unique ID for this refund attempt, for example INV-2026-1001-refund-1. Reuse it on a retry of the same attempt.
amountoptionalintegerMinor units. Leave out for a full refund. Send less for a partial refund.
reasonoptionalstringFree text. Shown as lastRefundReason on status.

Request

curl -X POST https://payments.plorea.no/payments/refund \
  -H "Authorization: Bearer $PLOREA_API_KEY" \
  -H "X-Environment: test" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "acme",
    "reference": "INV-2026-1001",
    "modificationReference": "INV-2026-1001-refund-1",
    "amount": 1000,
    "reason": "Customer requested refund"
  }'
$refund = Plorea::payments()->refund(
    reference: 'INV-2026-1001',
    modificationReference: 'INV-2026-1001-refund-1',
    amount: Amount::nok(1000),   // omit for a full refund
    reason: 'Customer requested refund',
);

// Persist this now. It never appears on the status endpoint.
$refund->refundPspReference;
const res = await fetch('https://payments.plorea.no/payments/refund', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.PLOREA_API_KEY}`,
    'X-Environment': 'test',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    platform: 'acme',
    reference: 'INV-2026-1001',
    modificationReference: 'INV-2026-1001-refund-1',
    amount: 1000,
    reason: 'Customer requested refund',
  }),
});
const refund = await res.json(); // save refund.refundPspReference

    "reference": "GOLDEN-2026-001",

Plorea recommended this on 2026-10-01. Pause with {"status": "paused"}. Resume with {"status": "active", "nextChargeAt": "…"}. Only an active subscription can be paused. To hold a trial, move its nextChargeAt instead. Verified

# Pause
curl -X PATCH https://payments.plorea.no/subscriptions/sub_test_golden \
  -H "Authorization: Bearer $PLOREA_API_KEY" \
  -H "X-Environment: test" \
  -H "Content-Type: application/json" \
  -d '{ "platform": "acme", "status": "paused" }'

Charge a subscription

POST/subscriptions/{subscriptionId}/charge

Charges the stored card now, outside the schedule. Use it for an upgrade difference or a one-off extra. The amount and VAT fall back to the subscription's values. Guide: Subscription workflows.

Body parameters

FieldTypeDescription
amountoptionalAmountDefault: the subscription amount.
vatRateoptionalnumberDefault: the subscription VAT rate.
vatAmountoptionalintegerDefault: the subscription VAT amount. Send it when you send a custom amount.
reasonoptionalstringFree text for your records.

Request

curl -X POST https://payments.plorea.no/subscriptions/sub_test_golden/charge \
  -H "Authorization: Bearer $PLOREA_API_KEY" \
  -H "X-Environment: test" \
  -H "Content-Type: application/json" \
  -d '{
    "platform": "acme",
    "reason": "Upgrade to Premium, rest of October",
    "amount": { "value": 5000, "currency": "NOK" },
    "vatRate": 0.25,
    "vatAmount": 1000
  }'
use MemberFlow\Plorea\Exceptions\ChargeFailedException;

try {
    $charge = Plorea::subscriptions()->charge(
        'sub_test_golden',
        amount: Amount::nok(5000),
        reason: 'Upgrade to Premium, rest of October',
        vatRate: 0.25,
        vatAmount: 1000,
    );
} catch (ChargeFailedException $e) {
    // 402: the card was declined
}
const res = await fetch('https://payments.plorea.no/subscriptions/sub_test_golden/charge', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.PLOREA_API_KEY}`,
    'X-Environment': 'test',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    platform: 'acme',
    reason: 'Upgrade to Premium, rest of October',
    amount: { value: 5000, currency: 'NOK' },
    vatRate: 0.25,
    vatAmount: 1000,
  }),
});
if (res.status === 402) { /* declined */ }
const charge = await res.json();
