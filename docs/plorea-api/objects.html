Reference

Objects and statuses

Every object the API returns, field by field. Each table comes from real, anonymised responses captured in the test environment. Each status table lists every value we have seen, and the values Plorea has stated but we could not observe.

How to read these tables

"Nullable" means the field is present but can be null. A field that is missing in some responses says so in the description. Unknown keys can appear at any time. Ignore keys you do not use, and never fail on an extra key.

Which endpoint returns what

EndpointShape
POST /subscriptionsCore fields plus retryPolicy. Echoes merchantOrgNr as the last key when sent. No accessEndsAt, no lastChargeAt. Verified
GET /subscriptions/{id}Full object, with merchantOrgNr since 2026-09-22. Verified
GET /subscriptions{externalId | tenantId, count, items}. Items have no retryPolicy, accessEndsAt or VAT. Items have merchantOrgNr since 2026-09-22. Verified
PATCH /subscriptions/{id}Core fields, VAT and card IDs, updatedAt. The same shape for a pause or a resume. Verified
GET …/charges{subscriptionId, items}. Adds merchantOrgNr to the envelope, not to the items, when a merchant is set. Verified
POST …/cancel{subscriptionId, status, canceledAt, accessEndsAt, reason}. Verified
POST …/reactivate{subscriptionId, tenantId, status, nextChargeAt, reactivatedAt, paymentMethodId, amount, interval, externalId, title}. Verified

activeBilling on schedule.Verified

Interval units

day, week, month, year. Combine with count, for example {"unit": "week", "count": 2} for every two weeks.

Error

Every error has the same body: one error string. Branch on the HTTP status. The message is a fixed template. See Errors and retries.
