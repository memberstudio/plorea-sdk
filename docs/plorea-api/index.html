Plorea Payments API

Take payments, store cards and bill subscriptions

Plorea is a Norwegian payment gateway on top of Adyen. One REST API gives you hosted payment links, embedded checkout, cards on file, recurring subscriptions and signed webhooks. These guides explain each workflow end to end, with request and response examples you can copy.

About these docs

An integrator wrote these docs. They are not official. Every fact comes from one of three sources: a call we made against the test environment, a statement from Plorea, or the Plorea PHP SDK. Badges show the source of each claim. Plorea is free to adopt, correct and extend this material.

What you can build

One-off payments

Create a hosted payment link, send the customer to it, and read the result by reference.

Embedded checkout

Start a session and render Adyen Drop-in on the web or in a native iOS or Android app.

Cards on file

Verify and store a card once. Charge it later without the customer present.

Subscriptions

Bill a stored card on a fixed interval. Plorea runs the scheduler for you.

Subscription workflows

Recipes for trials, price increases, upgrades, pauses, card swaps and cancellation.

Webhooks

Receive signed events when a payment is authorised, fails, is refunded or a subscription renews.

How a payment moves

Every payment has a reference that you choose. Plorea stores the payment under this reference. You use the same reference to read the status, refund or cancel. The diagram shows the normal path for a hosted payment link.

Base URL and authentication

All endpoints live under one host. Test and live use the same host. A header selects the environment.

Always send X-Environment

A POST /payments/refund without X-Environment uses the live credentials. With a test key, the call fails with 401 and "errorType": "security". Send the header on every request, also on reads. Verified

curl https://payments.plorea.no/payments/status/order-1001?platform=acme \
  -H "Authorization: Bearer $PLOREA_API_KEY" \
  -H "X-Environment: test" \
  -H "Accept: application/json"
use MemberFlow\Plorea\Facades\Plorea;

// config/plorea.php reads PLOREA_API_KEY and PLOREA_ENVIRONMENT.
$payment = Plorea::payments()->status('order-1001');

$payment->status;   // 'authorised'
$payment->isPaid(); // true
const res = await fetch(
  'https://payments.plorea.no/payments/status/order-1001?platform=acme',
  {
    headers: {
      Authorization: `Bearer ${process.env.PLOREA_API_KEY}`,
      'X-Environment': 'test',
      Accept: 'application/json',
    },
  },
);
const payment = await res.json();

Conventions

Amounts are in minor units

Send every amount as an integer in øre. 10000 means 100,00 kr. The currency is NOK. Payment links take a flat amount and currency. Subscriptions and charges take an object: {"value": 10000, "currency": "NOK"}.

The platform field

Plorea asks each integrator to identify itself with a platform value. Send it in the JSON body on POST and PATCH, and in the query string on GET. Plorea uses it for reporting only. It changes no behaviour. Stated by Plorea

References are yours

You choose the reference of a payment. Make it unique per payment attempt. The API does not deduplicate: two calls with the same reference create two payable links. See Retries and idempotency. Verified

Tenants and customers

A tenantId groups data for one of your own customers, for example one club or one shop. A customerId identifies the paying person inside that tenant. Plorea scopes stored cards and subscriptions by both. A call that mixes the IDs of two tenants fails with 403 Tenant mismatch.

Dates

Timestamps use ISO 8601 with an offset, for example 2026-11-01T00:00:00+00:00. Send dates in the same format.

Errors

An error response has a JSON body with one error string. Read the HTTP status, not the message. Messages are fixed templates and can change. See Errors and retries.

All endpoints

  • POST/payments/link Create a hosted payment link
  • GET/payments/status/{reference} Read a payment
  • POST/payments/refund Refund a settled payment
  • POST/payments/cancel Cancel an unsettled authorisation
  • GET/pay/{paymentLinkId} Read the public pay page data
  • POST/payments/session Start an embedded checkout session
  • POST/payment-methods/setup Store a card on a hosted page
  • POST/payment-methods/setup/session Store a card with Drop-in
  • GET/payment-methods/{id} Read a stored card
  • POST/subscriptions Create a subscription
  • GET/subscriptions List subscriptions
  • GET/subscriptions/{id} Read a subscription
  • PATCH/subscriptions/{id} Change price, card or labels
  • POST/subscriptions/{id}/charge Charge now
  • GET/subscriptions/{id}/charges List charges
  • POST/subscriptions/{id}/cancel Cancel at period end
  • POST/subscriptions/{id}/reactivate Undo a cancellation
